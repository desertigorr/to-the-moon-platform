# To the Moon — предиктор изменений движения транспорта

Система принимает бинарную телеметрию NDTP, сопоставляет её с расписанием и прогнозирует отклонение на остановке через 10–15 минут. Отдельные контейнеры: официальный эмулятор организаторов, Python/FastAPI backend, ML с двумя моделями CatBoost, React/nginx frontend.

## Запуск для жюри

Нужен Docker Desktop с Linux containers или Docker Engine с Compose v2. Python, Node.js и Java на компьютере жюри не нужны. При первой сборке требуется интернет для базовых образов и зависимостей; работа интерфейса не использует внешнюю картографию или облачный API.

1. Скопируйте из выданного организаторами набора:

```text
dataset/ndtp-telemetry-emulator.tar
dataset/validate/traffic.csv
dataset/validate/schedule_plan.csv
```

2. Из корня проекта запустите в PowerShell:

```powershell
./scripts/start-stack.ps1
```

Либо в Linux/macOS:

```sh
docker load -i dataset/ndtp-telemetry-emulator.tar
docker compose up -d --build --wait --wait-timeout 180
```

3. Откройте [дашборд](http://localhost:8080). Первые ТС появляются по мере поступления пакетов. Прогнозы обновляются каждые 5 секунд; для подтверждения прибытия по GPS нужны несколько наблюдений.

## Возможности

- Непрерывный NDTP, ограниченная история на каждое устройство, контроль повторов и времени доступности.
- Прогноз секунд отклонения и вероятности опоздания более 120 секунд на первой остановке в окне `(T+10 минут, T+15 минут]`.
- GPS-оценка последнего прибытия и `cur_dev_s`; неизвестное отклонение остаётся `null`.
- Геометрия из раннего исторического GPS; направление, привязка с учётом курса и предыдущего участка. Неподтверждённые связи отображаются пунктиром.
- Цвет риска на подходе к целевой остановке, карточка ТС, факторы конкретного прогноза Tree SHAP, измеренные признаки и рекомендации диспетчеру.
- Расчёт ETA резерва по введённым допущениям. Это сценарный расчёт времени, не оценка причинного эффекта на основной автобус.
- При потере сигнала координата сохраняется, ТС становится серым. ТС без плана скрыты по умолчанию; переключатель возвращает их.
- Первый выбор автобуса открывает карточку, повторный — его маршрут. «Все ТС» возвращает общий вид.
- Сохранение и воспроизведение последних десяти минут работы в интерфейсе.

## Источник движения

Основной режим `emulator_replay`: контроллер задаёт официальному неизменённому эмулятору исторические измерения через штатный REST API. Эмулятор отправляет NDTP на TCP 9201. Состояние автобусов и история модели обновляются только принятым NDTP, не чтением CSV.

По умолчанию воспроизводится фрагмент validate от 06.01.2026 12:30 UTC длительностью 30 минут, скорость 1×, затем новый цикл. Во всём фрагменте 21 устройство, план есть у 10 ТС. Время измерений и плана сдвинуто к моменту запуска. Это исторический сценарий, не текущие автобусы Москвы и не новый замер точности модели. [Подробности эмулятора](docs/emulator-scenario.md).

## Адреса и управление

| Адрес | Назначение |
|---|---|
| http://localhost:8080 | Дашборд |
| http://localhost:8000/docs | Swagger backend |
| http://localhost:8000/documentation/ | Сгенерированный PyDoc |
| http://localhost:8000/api/health | Состояние потока и ML |
| http://localhost:18080 | REST официального эмулятора |
| TCP localhost:9201 | Приём NDTP |

ML доступен внутри Docker по `http://ml:8001`. Порты по умолчанию привязаны к localhost. При конфликте остановите старый процесс или задайте порты в `.env` по примеру `.env.example`.

```sh
docker compose ps
docker compose logs --tail 100 backend ml emulator
docker compose down
```

Изменение настроек: скопируйте `.env.example` в `.env`, затем `docker compose up -d`. Обычная повторная сборка: `./scripts/start-stack.ps1`. Без сборки: `./scripts/start-stack.ps1 -NoBuild`.

## Файлы сдачи

В `submission/submission.csv` находится исходный прогноз регрессора для Data Science: `sample_id;prediction`. Скрипт упаковки проверяет все ID относительно `dataset/validate/points.csv`, наличие конечных прогнозов и отсутствие дублей.

Для формы решения нужен опубликованный Git-репозиторий либо подготовленный архив `submission/to-the-moon-source.zip`, если платформа принимает архивы. Публикация и отправка форм выполняются командой. В Git не входят данные организаторов, их Docker-образ, runtime-логи и локальные архивы разработки. Веса, геометрия, документация и lockfile входят в исходники. Обе формы сдачи обязательны согласно выданному ТЗ.

## Воспроизводимость и проверки

```sh
python -m venv .venv
# Активируйте окружение своей оболочкой
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Тесты настоящих моделей запускаются в ML-контейнере:

```powershell
docker compose run --rm --no-deps -v "${PWD}/tests:/tests:ro" ml python -m unittest discover -s /tests -p test_ml_service.py -v
```

Frontend: Node 24, pnpm 11.25.0; в `Frontend-To-the-Moon`: `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm test`, `pnpm build`.

Генераторы геометрии, документации и офлайн-оценки используют зависимости ML-образа. Команды приведены в документации. Проверка API и производительности: `python scripts/verify_stack.py`. Подготовка чистого архива: `python scripts/package_release.py`.
