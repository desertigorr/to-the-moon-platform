# Проверка решения жюри

## Старт

Следуйте корневому README: официальный tar-образ и два CSV в dataset, затем `scripts/start-stack.ps1` или `docker load` + `docker compose up`. Сервисы должны стать healthy, backend должен принимать NDTP. Дашборд: http://localhost:8080.

## Что проверить за 5–10 минут

1. На обзоре видно источник «Официальный эмулятор — историческое движение». Устройства появляются постепенно. Список и координаты обновляются по принятым пакетам.
2. Выберите ТС. В карточке есть текущая скорость, GPS-прибытие, прогноз секунд, вероятность опоздания, целевая остановка и горизонт 10–15 минут. Для ТС без цели показано отсутствие цели, а не фиктивный прогноз.
3. Выберите тот же автобус повторно. Откроется его маршрут. Сплошные линии восстановлены по ранней истории GPS, пунктирные — плановые связи без подтверждённой геометрии. Переключатель «Исходный GPS» позволяет сравнить исходную и привязанную позиции.
4. Подсветка участка показывает риск на подходе к целевой остановке. В тёмной теме используются оттенки синего; сверяйте их с легендой и текстовым статусом карточки («Риск задержки», «Отклонение от графика», «Низкий риск»). Нейтральные линии не имеют актуального прогноза. Это не утверждение о пробке на всём участке.
5. В карточке раскройте факторы: конкретные SHAP-вклады классификатора, направления влияния и наблюдения телеметрии. Они объясняют оценку модели, не устанавливают причину события.
6. В разделе «Рекомендации» выберите ТС с прогнозом. Задайте, например, подготовку резерва 2 минуты и путь 8 минут. Получите ETA и сравнение с прогнозируемым прибытием основного ТС. Это расчёт по вашим условиям, не команда на выпуск.
7. Проверьте обработку обрыва: `docker compose stop emulator`. Через 30 секунд без свежего GPS ТС серые и остаются на последних позициях; риск участков снимается. `docker compose start emulator` восстанавливает поток автоматически.
8. Проверьте отказ ML: `docker compose stop ml`. Координаты продолжают поступать, прогноз обозначается недоступным. `docker compose start ml` возобновляет расчёт.
9. «Сохранить запись» сохраняет до десяти минут; «Открыть запись» воспроизводит состояния без API. Существующие прогнозы не пересчитываются и не подменяются будущими кадрами.
10. Backend Swagger: http://localhost:8000/docs, PyDoc: http://localhost:8000/documentation/.

Первые минуты дают неполную историю. До GPS-подтверждения прибытия `cur_dev_s=null`. Контекстные ТС без плана можно включить переключателем. Это штатные состояния.

## Представление результата

Три прикладных модуля развёрнуты независимо: backend, ML, frontend. Четвёртый контейнер — официальный эмулятор. Бинарный NDTP проходит штатный приёмник. Модели — CatBoostRegressor и CatBoostClassifier, 74 общих признака; Tree SHAP объясняет индивидуальную классификацию риска. Данные о дверях отсутствуют в выданном наборе.

Метрики и ограничения находятся в metrics.md; качество модели по скрытой проверке не выводится из текущего потока. Геометрия использует только train GPS до начала сценария; фактические времена прибытия и метки в online-контур не передаются. Временной сдвиг и округление эмулятором раскрыты в emulator-scenario.md.

## Перед отправкой командой

- Запустить `python scripts/package_release.py` и проверить `submission/manifest.json`.
- В форму Data Science загрузить `submission/submission.csv`; подтвердить полученный платформенный score.
- Опубликовать эту версию репозитория и передать ссылку с README в форму решения. Архив исходников подготовлен отдельно; применять только если форма его принимает.
- Приложить инструкции и метрики, указать необходимые файлы организаторов. Не отправлять `.env`, runtime или материалы разработки.
