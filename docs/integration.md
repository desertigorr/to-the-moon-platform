# Архитектура и границы решения

```text
validate CSV → контроллер сценария → REST официального эмулятора
→ бинарный NDTP / TCP 9201 → декодер → история и последняя GPS-позиция
→ оценка прибытия + привязка к направленной геометрии
→ каждые 5 с: три таблицы → HTTP ML → регрессия + классификация + SHAP
→ состояние / уведомления / рекомендации → HTTP и WebSocket → React
```

## Телеметрия и причинность по времени

Backend — один процесс Python 3.12, FastAPI/asyncio. CPU-инференс выполняется в другом контейнере, NDTP его не ждёт. На устройство хранится до 10 000 пакетов за последние 15 минут. Для прогноза `T` допускаются только `event_time <= T` и `receive_time <= T`. Пакеты, очищенная история и последняя достоверная позиция разделены. Поздние сообщения не перемещают ТС назад. Медленный WebSocket-клиент получает новый snapshot вместо неограниченной очереди.

Новый цикл сценария сбрасывает историю, прибытия и предупреждения. После потери сигнала координата сохраняется. Без свежего сигнала прогноз не окрашивает ТС или участок в зелёный/красный.

## Прибытие и cur_dev_s

Прибытие оценивается по GPS в радиусе 50 м, скорости ≤5 км/ч, минимум двум наблюдениям на интервале ≥10 с; разрыв между ними ≤45 с. Повторная стоянка не создаёт нового прибытия. Нужно покинуть радиус 80 м, чтобы фиксировать следующую остановку. Порядок следует плановым прибытиям; неоднозначные случаи не подтверждаются.

`cur_dev_s = время первого наблюдения подтверждённого прибытия - время этой же остановки по плану`. Событие доступно только после получения подтверждающего пакета. До подтверждения — null, не ноль. Оценщик не читает `time_fact_begin`.

Дополнительные ограничения уверенности: прибытие не подтверждается, если стоянка началась более чем за 180 с до выбранного планового прибытия. Это защищает от подмены стоянки в депо будущим рейсом. Оценка действует 300 с от первого наблюдения, затем снова неизвестна; API сообщает `valid_until`. Для повторяющихся остановок учитывается последнее свежее отклонение. Это консервативная эвристика без дверных датчиков, а не гарантированное событие остановки. На выданном test она даёт известный cur_dev_s лишь для 120 из 353 целей. Сквозная ошибка с такой оценкой существенно выше ошибки модели на готовом признаке — см. metrics.md.

## Геометрия и привязка

`assets/geometry.json` содержит 387 направленных участков, восстановленных из train/traffic.csv с event_time и receive_time строго раньше 06.01.2026 12:30 UTC. Только координаты/скорость и плановая топология; фактические прибытия и labels не используются. У каждого участка есть время исходных наблюдений и источник. При сборке используются допустимые пары плановых остановок, удаляются повторы/скачки/разрывы, траектория упрощается. При нескольких проходах выбирается медианный по длине.

Во время работы к каждому плановому переходу подбирается соответствующая историческая траектория; иначе остаётся явная пунктирная связь по плану. Это восстановленная геометрия, не официальный дорожный граф. Привязка учитывает расстояние ≤80 м, направление движения, плановое время и предыдущий участок; неоднозначность не скрывается. Исходный `position` никогда не заменяется. Идентификатор `schedule-{tr_id}` — локальная нитка плана, не городской номер маршрута. `direction` описывает направленный участок.

Геометрия имеет версию; frontend применяет привязку только к соответствующему packet_id и graph_version. Для запуска более раннего сценария нужно пересобрать геометрию с более ранним cutoff либо отключить `GEOMETRY_PATH`.

## ML и объяснения

Модели загружаются один раз. FeatureBuilder строит 74 признака один раз на batch: отклонение, расстояния, курс, окна 60/180/300/600 с, скорость, доля стоянки, покрытие наблюдениями и плановые интервалы. Регрессор прогнозирует секунды, классификатор — вероятность отклонения >120 с на первой остановке в `(T+600, T+900]`.

Порог классификатора хранится в risk_meta.json, не подменяется UI. `early_risk_alert` требует известного cur_dev_s ≤120 с. Это не вероятность первого возникновения сбоя.

Факторы — индивидуальные [CatBoost Tree SHAP](https://catboost.ai/docs/en/concepts/shap-values) классификатора, умноженные на коэффициент калибровки. В API передаются пять наибольших по модулю вкладов, базовый log-odds и остаток (остальные признаки и численное ограничение калибровки). Их сумма восстанавливает logit итоговой вероятности. Это не процентные пункты, не объяснение регрессора и не доказательство причины задержки. Измеренные наблюдения идут отдельным полем.

## Участки риска и рекомендации

Риск приписывается последнему плановому переходу к целевой остановке, явно `basis=target_approach`. Он не утверждает, что там уже возникла пробка. Для общего физического направленного участка показывается наивысший актуальный уровень среди ТС. Устаревшие прогнозы и потерянный GPS исключаются. Неохваченные участки нейтральные.

Правила рекомендаций предлагают проверить связь, уточнить ситуацию, наблюдать динамику, проверить опережение, рассмотреть доступный резерв. Все требуют решения диспетчера, команды внешним системам не отправляются. Сценарий резерва: `ETA = сейчас + подготовка + путь`; сравнение с `план + прогноз задержки`. Входные минуты задаёт оператор. Пассажиропоток и причинный эффект не моделируются.

## Ограничения

Один день данных; нет гарантии переноса качества на другие дни. Классификатор даёт немало ложных срабатываний — численные метрики раскрыты отдельно. Контекстные ТС сохраняются, но не используются моделью как межмашинные признаки. Расписание загружается при старте; внешнее обновление требует перезапуска. Состояние и журнал уведомлений находятся в памяти; после перезапуска они не восстанавливаются. Raw NDTP пишется локально в artifacts/runtime, директорию следует контролировать при длительных запусках.

Текущая нагрузка мала. API допускает до 100 целей в одном batch; автоматическое горизонтальное масштабирование и разбиение большого парка не заявлены. CPU достаточен по локальным замерам. ONNX/TensorRT и ансамбль с нейросетью не реализованы.

## Воспроизведение артефактов

В PowerShell из корня, с загруженным ML-образом:

```powershell
docker compose run --rm --no-deps -v "${PWD}:/app" -w /app ml python -m scripts.geometry_builder
docker compose run --rm --no-deps -v "${PWD}:/app" -w /app ml python -m scripts.build_docs
```

Первая команда дополнительно требует train/traffic.csv и validate/schedule_plan.csv. Генерация геометрии и обучение не выполняются при обычном старте жюри. Для дообучения предоставлены transit_catboost.py и risk_model.py вместе с конфигурациями и метаданными; новые веса должны сохранять входной контракт и версии признаков.
