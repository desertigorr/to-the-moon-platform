# Производительность и дополнительные возможности

Текст для соответствующего поля формы решения:

> Система состоит из трёх отдельных прикладных контейнеров: FastAPI backend, ML-сервис с CatBoostRegressor и CatBoostClassifier, React/nginx BI-дашборд. Четвёртый контейнер — официальный NDTP-эмулятор организаторов. Исторический сценарий задаётся ему через штатный API; backend принимает именно бинарный NDTP. Прогнозы пересчитываются каждые 5 секунд, координаты передаются через WebSocket.
>
> В локальном минутном замере обработано 79 новых измерений без пропусков и отклонений при приёме; наблюдалось 18 ТС, из них 10 с расписанием. Для batch из 8 ТС время ML: p50 31 мс, p95 50 мс (13 измерений). HTTP health: p50 24 мс, p95 46 мс (60 запросов). Это замер небольшой локальной нагрузки; он не является оценкой полной задержки NDTP→экран или пределом масштабируемости.
>
> Дополнительные возможности: привязка GPS к восстановленным историческим участкам с явным статусом неоднозначности; оценка фактического прибытия и текущего отклонения; индивидуальные факторы риска Tree SHAP; подсветка подхода к целевой остановке; рекомендации диспетчеру; расчёт ETA резервного ТС по введённым условиям; сохранение и воспроизведение последних десяти минут состояния. Неизвестные ТС без расписания обрабатываются без ошибки и скрыты по умолчанию. При потере сигнала ТС становится серым и сохраняет позицию; при отказе ML телеметрия продолжает поступать. Проверены автоматическое восстановление после обоих отказов и запуск из чистого архива.
>
> Модельные факторы не заявляются установленными причинами задержки. Качество с готовым текущим отклонением и с его GPS-оценкой приведено раздельно в документации, включая ограничения и ухудшение сквозной MAE.
